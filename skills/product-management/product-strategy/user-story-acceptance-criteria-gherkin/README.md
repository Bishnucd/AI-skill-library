# User Story Acceptance Criteria Gherkin

## Description
Drafts agile user stories with testable Given-When-Then (Gherkin) acceptance criteria. Use when specifying developer-actionable user stories for sprint backlogs.

## Purpose
Ambiguous user stories lead to rework and disputed sprint deliveries. Structuring stories as role-action-benefit with Gherkin acceptance criteria guarantees clear testable boundaries.

## When to Use
- When executing user story acceptance criteria gherkin in production workflows.
- Use when structured standards, deterministic outputs, and error handling are required.

## When NOT to Use
- Ad-hoc, unstructured exploratory tasks where formal workflows add unnecessary overhead.
- Environments where required dependencies (Agile / Scrum, Gherkin Syntax) cannot be provisioned.

## Supported Technologies
- Agile / Scrum
- Gherkin Syntax
- Jira / Linear
- Markdown

## Example Use Cases
### Sprint Backlog Refinement
Preparing crisp, ready-for-development tickets before sprint planning meetings.

### BDD Test Automation Handoff
Providing QA engineers with Gherkin specifications ready for automated testing.

## Usage Instructions
1. Review the operational workflow defined in `SKILL.md`.
2. Ensure runtime dependencies (Agile / Scrum) are configured in the host environment.
3. Execute the workflow steps sequentially, validating intermediate outputs.
4. Verify the final generated artifact against declared acceptance criteria.
