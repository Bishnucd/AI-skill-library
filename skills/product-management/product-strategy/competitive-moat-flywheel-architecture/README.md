# Competitive Moat Flywheel Architecture

## Description
Architects defensible competitive moats and reinforcing growth flywheels based on Hamilton Helmer 7 Powers. Use when designing long-term competitive durability into products.

## Purpose
Features can be copied; moats cannot. Designing products around the 7 Powers (Network Effects, Switching Costs, Scale Economies, Counter-Positioning, Cornered Resource, Brand, Process Power) creates durability.

## When to Use
- When executing competitive moat flywheel architecture in production workflows.
- Use when structured standards, deterministic outputs, and error handling are required.

## When NOT to Use
- Ad-hoc, unstructured exploratory tasks where formal workflows add unnecessary overhead.
- Environments where required dependencies (7 Powers Framework, Flywheel Architecture) cannot be provisioned.

## Supported Technologies
- 7 Powers Framework
- Flywheel Architecture
- Competitive Strategy
- Network Effects

## Example Use Cases
### Developer Tool Platform Network Effects
Designing an open plugin marketplace that increases platform value exponentially as more developers join.

### Enterprise Data Lakehouse Switching Costs
Architecting proprietary metadata indexing layers that make migrating away prohibitively complex.

1. Review the operational workflow defined in `SKILL.md`.
2. Ensure runtime dependencies (7 Powers Framework) are configured in the host environment.
3. Execute the workflow steps sequentially, validating intermediate outputs.
4. Verify the final generated artifact against declared acceptance criteria.
