# Kano Model Feature Satisfaction Analysis

## Description
Classifies product features into Must-Be, Performance, Attractive, and Indifferent tiers using the Kano Model questionnaire. Use when prioritizing roadmap investments for maximum customer delight.

## Purpose
The Kano Model evaluates feature impact on customer satisfaction using functional (feature present) and dysfunctional (feature absent) question pairs, preventing over-investment in basic must-haves.

## When to Use
- When executing kano model feature satisfaction analysis in production workflows.
- Use when structured standards, deterministic outputs, and error handling are required.

## When NOT to Use
- Ad-hoc, unstructured exploratory tasks where formal workflows add unnecessary overhead.
- Environments where required dependencies (Kano Model, Customer Satisfaction) cannot be provisioned.

## Supported Technologies
- Kano Model
- Customer Satisfaction
- Feature Prioritization
- Product Management

## Example Use Cases
### Mobile Banking App Roadmap Prioritization
Confirming biometric login is a baseline Must-Be while cash-back rewards serve as an Attractive delight driver.

### Enterprise B2B Software Feature Trim
Identifying Indifferent features that consume engineering time without moving customer satisfaction.
