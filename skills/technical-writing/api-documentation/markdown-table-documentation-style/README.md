# Markdown Table Documentation Style

## Description
Formats readable, consistent Markdown reference tables for parameter listings and status codes. Use when presenting structured reference data in documentation files.

## Purpose
Markdown tables provide dense, structured reference information. Following consistent styling rules (aligned delimiters, brief headers, backtick code formatting) ensures readability.

## When to Use
- When executing markdown table documentation style in production workflows.
- Use when structured standards, deterministic outputs, and error handling are required.

## When NOT to Use
- Ad-hoc, unstructured exploratory tasks where formal workflows add unnecessary overhead.
- Environments where required dependencies (Markdown Tables, GitHub Flavored Markdown) cannot be provisioned.

## Supported Technologies
- Markdown Tables
- GitHub Flavored Markdown
- Technical Style Guide
- Documentation

## Example Use Cases
### API Query Parameter Reference Table
Documenting 15 query parameters with types, default values, and validation constraints in a tidy table.

### Environment Variable Configuration Table
Listing Docker container environment variables with required flags and descriptions in README.md.
