# SOP Writing Skill

## Description
Creates clear, maintainable Standard Operating Procedures (SOPs) from raw process knowledge, with version control, review cycles, and distribution readiness.

## Purpose
Transforms informal "how we do things" into documented, auditable procedures that teams can follow consistently and improve over time.

## When to Use
- Onboarding new team members requires documented processes
- Compliance audits need evidence of documented procedures
- Process knowledge is siloed in individuals' heads
- Existing SOPs are outdated, inconsistent, or missing

## When NOT to Use
- One-off tasks that won't be repeated
- Highly creative or exploratory work with no repeatable steps
- Processes that change weekly (document the framework, not the details)

## Supported Technologies
- Markdown, Confluence, Notion, Google Docs, GitBook
- Version control (Git) for SOP change management
- Review/approval workflows (PRs, signatures)

## Dependencies
- Access to subject matter experts for process extraction
- Template or style guide for consistency
- Review/approval process defined

## Example Use Cases
### Use Case 1: Incident Response Runbook
Create an SOP for handling production incidents: detection, escalation, communication, resolution, postmortem.

### Use Case 2: Code Release Checklist
Document the step-by-step release process including approvals, staging validation, rollback procedures.

## Usage Instructions
1. Interview SMEs to capture current process steps
2. Structure into: Purpose, Scope, Prerequisites, Procedure, References, Revision History
3. Add visual aids (flowcharts, screenshots) where helpful
4. Route for review/approval per organizational policy
5. Publish to accessible location with version control
6. Schedule periodic review (quarterly or per major change)

## Limitations
- Requires SME time investment
- SOPs can become outdated without review discipline
- Over-documentation creates maintenance burden
- Cultural resistance to "bureaucracy" possible
