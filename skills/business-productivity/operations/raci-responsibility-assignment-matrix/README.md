# Raci Responsibility Assignment Matrix

## Description
Maps project deliverables and operational decisions to RACI roles (Responsible, Accountable, Consulted, Informed). Use when clarifying team roles and eliminating cross-functional bottlenecks.

## Purpose
Unclear role ownership causes decision gridlock and missed responsibilities. A RACI matrix ensures every task has exactly one Accountable owner alongside clearly designated Responsible contributors.

## When to Use
- When executing raci responsibility assignment matrix in production workflows.
- Use when structured standards, deterministic outputs, and error handling are required.

## When NOT to Use
- Ad-hoc, unstructured exploratory tasks where formal workflows add unnecessary overhead.
- Environments where required dependencies (RACI Framework, Governance) cannot be provisioned.

## Supported Technologies
- RACI Framework
- Governance
- Spreadsheets
- Markdown

## Example Use Cases
### Cross-Functional Product Launches
Clarifying responsibilities between Product, Engineering, Legal, and Marketing before major releases.

### Incident Commander Roles
Defining clear emergency decision rights during major production outages.

## Usage Instructions
1. Review the operational workflow defined in `SKILL.md`.
2. Ensure runtime dependencies (RACI Framework) are configured in the host environment.
3. Execute the workflow steps sequentially, validating intermediate outputs.
4. Verify the final generated artifact against declared acceptance criteria.
