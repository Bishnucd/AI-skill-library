# Statement Of Work Authoring

## Description
Drafts legally robust Statements of Work (SOW) outlining project scope, deliverables, acceptance criteria, and milestones. Use when contracting professional services or software development engagements.

## Purpose
Ambiguous Statements of Work lead to scope creep and payment disputes. A rigorous SOW specifies exact deliverables, milestones, out-of-scope boundaries, and formal acceptance criteria.

## When to Use
- When executing statement of work authoring in production workflows.
- Use when structured standards, deterministic outputs, and error handling are required.

## When NOT to Use
- Ad-hoc, unstructured exploratory tasks where formal workflows add unnecessary overhead.
- Environments where required dependencies (Markdown, Contract Standards) cannot be provisioned.

## Supported Technologies
- Markdown
- Contract Standards
- Git
- DocuSign

## Example Use Cases
### Consulting Engagement SOW
Formalizing project deliverables and payment milestones for client contracts.

### Vendor Subcontracting
Aligning external specialist contractor scope with enterprise master agreements.

## Usage Instructions
1. Review the operational workflow defined in `SKILL.md`.
2. Ensure runtime dependencies (Markdown) are configured in the host environment.
3. Execute the workflow steps sequentially, validating intermediate outputs.
4. Verify the final generated artifact against declared acceptance criteria.
