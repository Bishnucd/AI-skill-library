# Proof Of Concept Poc Success Charter

## Description
Authors timeboxed Proof of Concept (POC) charters with explicit, measurable technical success criteria. Use when converting prospect technical evaluations into commercial software purchases.

## Purpose
Unstructured POCs drag on indefinitely without closing. A POC success charter establishes a 30-day window, defines 3-5 objective technical pass criteria, and commits to purchase upon success.

## When to Use
- When executing proof of concept poc success charter in production workflows.
- Use when structured standards, deterministic outputs, and error handling are required.

## When NOT to Use
- Ad-hoc, unstructured exploratory tasks where formal workflows add unnecessary overhead.
- Environments where required dependencies (POC Charter, Evaluation Criteria) cannot be provisioned.

## Supported Technologies
- POC Charter
- Evaluation Criteria
- Presales Engineering
- Markdown

## Example Use Cases
### Presales POC Conversion Acceleration
Preventing perpetual trial periods by locking prospects into pre-agreed purchase criteria.

### Enterprise Software Technical Evaluation
Aligning prospect IT evaluators on objective testing metrics rather than subjective opinions.

## Usage Instructions
1. Review the operational workflow defined in `SKILL.md`.
2. Ensure runtime dependencies (POC Charter) are configured in the host environment.
3. Execute the workflow steps sequentially, validating intermediate outputs.
4. Verify the final generated artifact against declared acceptance criteria.
